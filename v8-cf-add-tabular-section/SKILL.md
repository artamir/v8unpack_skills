# v8-cf-add-tabular-section

## Назначение

Скилл добавляет новую табличную часть в объект метаданных 1С (документ, справочник, план видов характеристик и т.п.) в исходниках распакованной конфигурации (JSON-формат v8unpack).

Базовый режим: создаётся пустая табличная часть (без реквизитов).

Расширенный режим: если пользователь передаёт набор колонок, после создания пустой ТЧ запускается добавление колонок в форму через `tools/add_form_column.py` (связанный скилл `v8-cf-add-form-column`).

## Поддерживаемые объекты

- `Document` — документы
- `Catalog` — справочники
- `ChartOfCharacteristicType` — планы видов характеристик
- другие объекты, имеющие `header[0][3]` с UUID `21c53e09-8950-4b5e-a6a0-1054f1bbc274`

## Расположение табличных частей в JSON

Файл объекта обычно расположен как:

- `src/<Проект>/cf/<Тип>/<ИмяОбъекта>/<Тип>.json`
- или `src/<Проект>/<Тип>/<ИмяОбъекта>/<Тип>.json` (как в `NLTrade_invoice`)

Табличные части хранятся в `header[0][3]`:

```json
[
  "21c53e09-8950-4b5e-a6a0-1054f1bbc274",  // UUID типа "TabularSection" — ФИКСИРОВАННЫЙ
  "2",                                       // счётчик (количество табличных частей)
  [ <ТЧ_1_entry> ],                         // первая табличная часть
  [ <ТЧ_2_entry> ]                          // вторая табличная часть
]
```

## Структура одной табличной части

```json
[
  [                                          // [0] — определение ТЧ
    "1",                                     //     версия (или маркер)
    [                                        //     свойства ТЧ
      "11",                                  //     тип (ФИКСИРОВАННЫЙ)
      "новый-uuid-1",                        //     внутренний UUID 1
      "новый-uuid-2",                        //     внутренний UUID 2
      "новый-uuid-3",                        //     внутренний UUID 3
      "новый-uuid-4",                        //     внутренний UUID 4
      [                                      //     блок имени
        "0",
        [
          "1",                               //     или "3" — маркер версии метаданных
          ["1", "0", "uuid-самой-тч"],       //     уникальный UUID этой табличной части
          "\"ИмяТЧ\"",                       //     имя в формате 1С (в кавычках)
          ["1", "\"ru\"", "\"Синоним ТЧ\""], //     синоним
          "\"\"",                            //     комментарий
          "0",
          "0"
        ]
      ],
      "0",
      ["0"],
      ["0"]
    ]
  ],
  1,                                         // [1] — флаг наличия реквизитов (0 или 1)
  [                                          // [2] — блок реквизитов
    "888744e1-b616-11d4-9436-004095e12fc7",  //     UUID типа "Attribute" — ФИКСИРОВАННЫЙ
    "0"                                      //     счётчик реквизитов (0 = пусто)
  ]
]
```

> **Примечание 1:** Для пустой табличной части (без реквизитов) блок реквизитов должен содержать только UUID и счётчик `"0"`.
>
> **Примечание 2:** В разных конфигурациях внутри блока имени позиции могут отличаться. Надёжнее искать поля по форме данных:
> - UUID-блок: массив вида `['0'|'1', '0'|'1', '<uuid>']`
> - техническое имя: строка в кавычках
> - синоним: массив вида `['1', '"ru"', '"..."']`

## Алгоритм добавления

### 1. Определить объект и путь к JSON

Найти файл:

- `src/<Проект>/cf/<Тип>/<ИмяОбъекта>/<Тип>.json`, или
- `src/<Проект>/<Тип>/<ИмяОбъекта>/<Тип>.json`

Примеры:

- `src/NLTrade/cf/Document/РасходнаяНакладная/Document.json`
- `src/NLTrade_invoice/Document/Инвойс/Document.json`

### 2. Создать бэкап файла

```
cp <путь/к/файлу.json> <путь/к/файлу.json>.bak
```

### 3. Прочитать существующую ТЧ как шаблон

Взять первую ТЧ из `header[0][3][2]` как шаблон для клонирования.

### 4. Сгенерировать новые UUID

Нужно 5 новых UUID:
- 4 внутренних (`uuid-1` … `uuid-4`) — для `header[0][3][N][0][1][1..4]`
- 1 идентификатор ТЧ (`uuid-тч`) — для `header[0][3][N][0][1][5][1][2]`

Генерация через Python:
```python
import uuid
new_uuids = [str(uuid.uuid4()) for _ in range(5)]
```

### 5. Обновить имя и синоним

В блоке имени (`header[0][3][N][0][1][5][1]`):
- позиция `[3]` = `"\"ИмяТЧ\""` — техническое имя (в кавычках 1С-стиля)
- позиция `[4]` = `["1", "\"ru\"", "\"Синоним\""]` — синоним на русском

### 6. Обновить счётчик

```python
data['header'][0][3][1] = str(int(data['header'][0][3][1]) + 1)
```

### 7. Добавить новую ТЧ в список

```python
data['header'][0][3].append(new_ts_entry)
```

### 8. Принудительно сделать ТЧ пустой

Новая ТЧ создаётся без реквизитов:

```python
# блок реквизитов ТЧ
new_ts_entry[2] = [
  '888744e1-b616-11d4-9436-004095e12fc7',
  '0'
]
```

### 9. Если переданы колонки — добавить колонки на форму

1. После создания пустой ТЧ пройти по списку колонок.
2. Для каждой колонки вызвать `tools/add_form_column.py`.
3. Если форма или таблица формы не переданы, остановиться с понятной ошибкой и запросить параметры формы.

Пример последовательного вызова:

```bash
python tools/add_form_column.py <путь_к_DocumentForm.elem.json> <ИмяТаблицыНаФорме> <Колонка1> "<Заголовок1>"
python tools/add_form_column.py <путь_к_DocumentForm.elem.json> <ИмяТаблицыНаФорме> <Колонка2> "<Заголовок2>"
```

### 10. Сохранить файл

Сохранить в кодировке UTF-8 без BOM, с отступами 2 пробела:
```python
import json
with open(path, 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

## Скрипт автоматизации

Файл: `tools/add_tabular_section.py`

Создаёт пустую табличную часть в объекте JSON и (опционально) добавляет колонки на форму.

### Вызов

```bash
python tools/add_tabular_section.py <object_json> <tabular_name> [tabular_synonym]
```

Опции:

- `--columns Кол1,Кол2,Кол3` — список колонок для добавления на форму после создания ТЧ
- `--form-elem-json <путь>` — путь к `DocumentForm.elem.json` (обязательно при `--columns`)
- `--form-table-name <имя>` — имя таблицы на форме (по умолчанию = `<tabular_name>`)

Примеры:

```bash
# 1) Создать пустую ТЧ
python tools/add_tabular_section.py \
  src/NLTrade/cf/Document/РасходнаяНакладная/Document.json \
  Позиции "Позиции"

# 2) Создать ТЧ + добавить колонки на форму
python tools/add_tabular_section.py \
  src/NLTrade/cf/Document/РасходнаяНакладная/Document.json \
  Позиции "Позиции" \
  --columns Номенклатура,Количество,Цена \
  --form-elem-json src/NLTrade/cf/Document/РасходнаяНакладная/DocumentForm/ФормаДокумента/DocumentForm.elem.json \
  --form-table-name Позиции
```

## Ключевые UUID (фиксированные)

| UUID | Назначение |
|------|-----------|
| `21c53e09-8950-4b5e-a6a0-1054f1bbc274` | Тип блока "TabularSection" |
| `888744e1-b616-11d4-9436-004095e12fc7` | Тип блока "Attribute" (реквизиты ТЧ) |

## Что НЕ требуется

- **Регистрация в Configuration.json** — табличные части не являются самостоятельными объектами конфигурации (в отличие от перечислений).
- **Создание отдельных файлов** — вся ТЧ хранится внутри JSON-файла объекта.

## Критерии успешности

- `header[0][3][1]` (счётчик ТЧ) увеличен на 1.
- Новая ТЧ добавлена в конец списка `header[0][3]`.
- Все 5 UUID в новой ТЧ уникальны и сгенерированы заново.
- Имя и синоним соответствуют запросу.
- Новая ТЧ пустая: блок реквизитов содержит UUID типа атрибутов и счётчик `"0"`.
- Если переданы колонки, каждая колонка добавлена через `tools/add_form_column.py`.
- Файл сохранён в UTF-8, JSON валиден.

## Добавление реквизитов в новую ТЧ

Для добавления реквизитов в созданную ТЧ — используй тот же принцип клонирования:
- Возьми существующий реквизит из блока реквизитов (`header[0][3][N][2]`) как шаблон
- Обнови UUID реквизита и его имя/тип
- Обнови счётчик `header[0][3][N][2][1]`
- Структура реквизита ТЧ аналогична реквизиту объекта в `header[0][5]`
