# v8-cf-add-ts-attribute

## Назначение

Скилл добавляет новый реквизит в уже существующую табличную часть объекта метаданных 1С (документ, справочник и т.п.) в исходниках распакованной конфигурации (JSON-формат v8unpack).

Скрипт: `tools/add_ts_attribute.py`

## Поддерживаемые объекты

- `Document` — документы
- `Catalog` — справочники
- `ChartOfCharacteristicType` — планы видов характеристик
- любые объекты с `header[0][3]` (блок TabularSection, UUID `21c53e09-8950-4b5e-a6a0-1054f1bbc274`)

## Расположение объектных JSON

- `src/<Проект>/cf/<Тип>/<ИмяОбъекта>/<Тип>.json`  — формат NLTrade
- `src/<Проект>/<Тип>/<ИмяОбъекта>/<Тип>.json`    — формат NLTrade_invoice (без `/cf/`)

## Использование скрипта

```bash
python tools/add_ts_attribute.py <object_json> <ts_name> <attr_name> [attr_synonym] \
    [--type <TYPE_SPEC>] \
    [--form-elem-json <DocumentForm.elem.json>] \
    [--form-table-name <имя_таблицы_на_форме>]
```

### Параметры

| Параметр | Описание |
|---|---|
| `object_json` | Путь к `Document.json`, `Catalog.json` и т.п. |
| `ts_name` | Техническое имя табличной части (например `Товары`) |
| `attr_name` | Техническое имя нового реквизита (например `Количество`) |
| `attr_synonym` | Синоним (необязательно; по умолчанию = `attr_name`) |
| `--type` | Спецификация типа данных (см. ниже) |
| `--form-elem-json` | Путь к `DocumentForm.elem.json` — для добавления колонки на форму |
| `--form-table-name` | Имя таблицы на форме (обычно совпадает с именем ТЧ) |

### Спецификации типа (`--type`)

| Формат | Описание | Пример |
|---|---|---|
| `N:ширина:точность:ненулевое` | Число | `N:10:2:0` |
| `S:длина` | Строка фиксированной длины | `S:100` |
| `S` | Строка неограниченной длины | `S` |
| `B` | Булево | `B` |
| `D` | Дата | `D` |
| `DT` | Дата и время | `DT` |
| `T` | Время | `T` |
| `#:uuid` | Ссылка на объект по UUID | `#:d2337ea8-...` |

**Без `--type`**: клонирует тип первого существующего реквизита ТЧ.  
**Если ТЧ пустая и `--type` не указан**: использует `N:10:2:0` (Число 10.2).

## Примеры

### Добавить числовой реквизит в существующую ТЧ

```bash
python tools/add_ts_attribute.py \
  src/NLTrade_invoice/Document/Инвойс/Document.json \
  ТоварыИнвойса Количество "Количество" --type N:10:4:0
```

### Добавить строковый реквизит

```bash
python tools/add_ts_attribute.py \
  src/NLTrade_invoice/Document/Инвойс/Document.json \
  ТоварыИнвойса Примечание "Примечание" --type S:200
```

### Добавить реквизит-ссылку на справочник

```bash
python tools/add_ts_attribute.py \
  src/NLTrade/cf/Document/РасходнаяНакладная/Document.json \
  Товары Номенклатура "Номенклатура" --type "#:d2337ea8-e5ff-4f48-b767-ac647eae2536"
```

### Добавить реквизит и сразу колонку на форму

```bash
python tools/add_ts_attribute.py \
  src/NLTrade_invoice/Document/Инвойс/Document.json \
  ТоварыИнвойса Количество "Количество" --type N:10:4:0 \
  --form-elem-json "src/NLTrade_invoice/Document/Инвойс/DocumentForm/ФормаДокумента/DocumentForm.elem.json" \
  --form-table-name ТоварыИнвойса
```

## Структура атрибута в JSON

Реквизиты ТЧ хранятся в `ts_entry[2]`:

```json
[
  "888744e1-b616-11d4-9436-004095e12fc7",  // UUID блока реквизитов (фиксированный)
  "2",                                      // счётчик реквизитов
  [ <attr_entry_1> ],
  [ <attr_entry_2> ]
]
```

Каждый `attr_entry`:

```json
[
  [
    "8",                          // формат "8" (новый) или "6" (старый)
    ["27",
      ["2",                       // desc_2
        [                         // name_block — desc_2[1]
          "3",                    //   "3" (новый) или "1" (старый)
          ["1", "0", "<uuid>"],   //   uuid_sub — name_block[1]
          "\"ТехИмя\"",           //   техническое имя — name_block[2]
          ["1", "\"ru\"", "\"Синоним\""], // синоним — name_block[3]
          "\"\"", "0", "0",
          "00000000-...", "0"
        ],
        ["\"Pattern\"", ["\"N\"", "10", "2", "0"]]  // тип — desc_2[2]
      ],
      "0", ["0"], ["0"], "0", ...
    ],
    "0", "0", "1"
  ],
  "0"
]
```

**ВАЖНО**: имя и синоним хранятся внутри `name_block` (`desc_2[1]`), а не на уровне `desc_2`!

**Отличие форматов**:
- Старый (`"6"`, NLTrade): `name_block[0]` = `"1"`, `uuid_sub` = `["0", "0", uuid]`
- Новый (`"8"`, NLTrade_invoice): `name_block[0]` = `"3"`, `uuid_sub` = `["1", "0", uuid]`

Скрипт автоматически определяет формат объекта и использует соответствующий шаблон.
При пустой ТЧ предпочитает клонировать реальный атрибут из другой ТЧ того же объекта.

## Порядок работы агента

1. **Найти объектный JSON**: определить путь к `Document.json` / `Catalog.json` по имени объекта и проекту.
2. **Уточнить имя ТЧ**: техническое имя табличной части (без синонима), как оно задано в конфигурации.
3. **Уточнить параметры реквизита**: имя, синоним, тип.
4. **Создать бэкап и выполнить скрипт**.
5. **Если нужна колонка на форме**: дополнительно выполнить скрипт с `--form-elem-json` и `--form-table-name`, или использовать скилл `v8-cf-add-form-column` отдельно.
6. **При необходимости**: пересобрать CF через скилл `v8-cf-v8pack`.

## Связанные скиллы

- `v8-cf-add-tabular-section` — создание новой ТЧ
- `v8-cf-add-form-column` — добавление колонки на форму (обычная форма)
- `v8-cf-v8pack` — упаковка исходников в .cf
